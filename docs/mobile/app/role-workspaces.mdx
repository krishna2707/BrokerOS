## One Application, 14 Dedicated Workspaces

Real estate operations encompass multiple distinct field and office roles: telecallers dialing cold leads, sales executives meeting clients at construction sites, sourcing managers recruiting independent brokers, and post-sales agents collecting milestone payments.

Rather than fragmenting into multiple applications, BrokerOS runs a **single unified mobile application**. Upon login, the dashboard shell (`apps/mobile/app/(dashboard)/_layout.tsx`) reads the employee's role from their server session and dynamically generates an optimized bottom tab bar and screen hierarchy.

---

## Dynamic Navigation Engine

The mobile navigation engine relies on two central constants defined in [`apps/mobile/constants/navigation.tsx`](https://github.com/trybrokeros/BrokerOS/blob/main/apps/mobile/constants/navigation.tsx):

1. **`ALL_POSSIBLE_SCREENS`**: Declares every registered screen route, title, icon, and authorized roles.
2. **`getNavLinksForRole(userRole)`**: A pure mapping function that returns the exact tab items allowed for the authenticated role.

```tsx
// Inside apps/mobile/app/(dashboard)/_layout.tsx
const userRole = roleCode || 'UNKNOWN';
const navLinks = getNavLinksForRole(userRole);

return (
  <Tabs ...>
    {ALL_POSSIBLE_SCREENS.map((link) => {
      const isVisible = navLinks.some((nl) => nl.name === link.name);
      return (
        <Tabs.Screen
          key={link.name}
          name={link.name}
          options={{
            title: link.title,
            tabBarLabel: link.title,
            // Hides unauthorized routes completely from deep linking
            href: isVisible ? undefined : null,
            tabBarItemStyle: { display: isVisible ? 'flex' : 'none' },
            tabBarIcon: ({ color, size }) => renderTabIcon(link.icon, color, size),
          }}
        />
      );
    })}
  </Tabs>
);
```

Unauthorized tabs receive `href: null` and `display: 'none'`, preventing unauthorized users from accessing or deep linking into prohibited routes.

## Role-by-Role Workspace Directory

### 1. Pre-Sales Telecaller (`PRE_SALES`)
Focused entirely on high-throughput phone outreach, queue execution, and disposition logging.

| Bottom Tab | Route | Functionality |
| :--- | :--- | :--- |
| **Dashboard** | `pre-sales/index` | Daily call queue, auto-dialer launcher, progress against daily call target. |
| **Leads** | `pre-sales/lead-management` | Lead catalog with stage, temperature (HOT/WARM/COLD), and search filters. |
| **Analytics** | `pre-sales/analytics` | Personal connect rate, total call minutes, and completed follow-ups. |
| **Settings** | `pre-sales/settings` | Recording folder picker (SAF), audio sync status, and account settings. |

---

### 2. Pre-Sales Manager (`PRE_SALES_MANAGER`)
Provides operational supervision over telecaller teams without personal call queues.

| Bottom Tab | Route | Functionality |

| **Leads** | `pre-sales-manager/lead-management` | Team-wide lead pipeline with reassignment actions. |

| **Analytics** | `pre-sales-manager/analytics` | Comparative performance charts and missed follow-up tracking. |
| **Settings** | `pre-sales-manager/settings` | Team-wide calling thresholds and script guidelines. |

### 14. Global Header Utilities
Available in the top header regardless of the active role:

- **Notifications Center** (`notifications.tsx`): Real-time FCM and Socket.IO alerts with interactive deep links.
- **Team Chat** (`chat/index.tsx`, `chat/[id].tsx`): Real-time team messaging and lead profile sharing.
- **Sign Out**: Clears hardware-backed tokens, halts background location services, and unregisters telephony listeners.
